## 💡 PRG PCCP - 충돌위험 찾기[[문제 링크](https://school.programmers.co.kr/learn/courses/30/lessons/340211)]

| 항목 | 내용 |
|------|------|
| 문제 유형 | `구현`, `시뮬레이션` |
| 사용 알고리즘 | `Simulation` |
| 난이도 | `Lev.2` |

### ✅ 문제 설명

[문제 요약]

- 물류 센터에 자동 운송 시스템이 있음
- 물류 센터는 (r, c)로 표현되는 n개의 포인트가 존재하며, 각 포인트는 1~n까지 서로 다른 번호를 가짐
- 로봇마다 정해진 운송 경로가 존재함
- 운송 경로는 m개의 포인트로 구성되고, 로봇은 첫 포인트에서 시작해 할당된 포인트를 순서대로 방문함
- 운송 시스템에 사용되는 로봇은 X대이고, 모든 로봇은 0초에 동시에 출발함
- 로봇은 1초에 한 칸씩 이동가능
- 다음 포인트로 이동할 때는 항상 최단 경로로 이동하는데, 그런 곳이 여러 개일 경우 r좌표가 변하는 이동 > c좌표가 변하는 이동
- 마지막 포인트에 도착한 로봇은 운송을 마치고 물류 센터를 벗어남
- 이동 중 같은 좌표에 로봇이 2대 이상 모인다면 충돌할 가능성이 있는 위험 상황으로 판단
- 현재 설정대로 운영했을 때, '위험 상황'이 총 몇 번 일어나는지 알고 싶음

[제약 사항]

- 2 <= points 길이 = n <= 100
- points[i]는 (r, c)를 나타내는 길이가 2인 정수 배열
- 1 <= r <= 100
- 1 <= c <= 100
- 같은 좌표에 여러 포인트가 존재하는 입력은 주어지지 않음
- 2 <= routes의 길이 = 로봇의 수 = X <= 100
- 같은 포인트를 연속으로 방문하는 입력은 주어지지 않음

### 🔍 풀이 접근
- 현재 장애물이 없고, 이동 규칙이 r방향 우선 -> c방향으로 결정되어 있으므로 경로는 유일해진다
- 따라서 경로 탐색 알고리즘인 BFS까지는 필요없다
- 예를 들어, (1, 2) -> (4, 3)이라고 하면 r을 먼저 변화시키고 c를 변화시키는 경로를 만들면 된다
- (1, 2) -> [(2, 2) (3, 2) (4, 2)] -> (4, 3)
- 경로를 표현하는 형식은 vector<{ t, r, c }>이다
- 이제 경로로부터 동시에 같은 위치에 오는 '위험 상황'을 찾아야 함
- 같은 시간에 같은 좌표에 있는 경우를 찾아야 함
- 3차원 visited 배열을 만들어서 체크하기에는 t가 최대 2만정도라서 2만 x 100 x 100 = 2억
- TLE가 발생할 가능성이 높다
- 따라서 unordered_map 혹은 map을 사용하자

### 💡 핵심 로직

- 공간 좌표 `(r, c)`만으로는 충돌을 판단할 수 없고, 시간까지 포함한 `(t, r, c)`를 하나의 상태로 만들어 카운팅한다.

### 📌 배운 점
- 시간+위치를 하나의 상태로 관리해서 중복을 체크하는 시뮬레이션 문제 해결
- map 자료구조 사용 이해
- unordered_map vs map의 차이
